# Solos Gems, AI Tools for Solopreneurs

Static site, no build step. 16 tool reviews + homepage + about page. Rebranded from "Solo/Stack", domain: solosgems.com (confirmed available, $10.46/year via Cloudflare Registrar as of this writing).

## Logo

The header logo is a hand-built inline SVG + CSS combo, not an image file, a faceted gem icon next to a "SOLOS GEMS" wordmark styled like the classic *Star Wars* logo treatment: bold condensed caps, gold gradient fill, dark outline stroke, and a slight vertical stretch for that beveled block-letter look. It's defined once per page in the `<header>` and styled via `.gem-icon` / `.logo-word` in `styles.css`, no external font or image dependency, so it renders identically everywhere without extra requests.

## SEO

Every page now ships with: a `solosgems.com` canonical URL, Open Graph + Twitter Card tags (using `images/og-default.png`, a generated 1200×630 branded social card), an SVG favicon (`favicon.svg`), JSON-LD structured data (`WebSite`/`ItemList` on the homepage, `Article` + `BreadcrumbList` + `Review` on every review), a visible breadcrumb trail on review pages, explicit `width`/`height` on all images to prevent layout shift, and titles trimmed to fit Google's ~60-character SERP limit. `robots.txt` and `sitemap.xml` both point at the real domain, and the sitemap has `lastmod`/`priority` set.

Still worth doing once there's real traffic: submit `sitemap.xml` in Google Search Console and Bing Webmaster Tools, and consider per-review OG images instead of the single shared one if social shares become a meaningful traffic source.

## AI answer engines (AEO)

Beyond classic search SEO, every review now has a "Quick Answer" callout (the `.answer-capsule` box) right at the top, before the spec plate: a tight 2-3 sentence, fact-dense summary (rank, score, price, best-for, verdict) written to be easy for ChatGPT, Perplexity, and Google AI Overviews to quote directly. `robots.txt` explicitly allows the major AI crawlers (GPTBot, PerplexityBot, ClaudeBot, OAI-SearchBot, Google-Extended) in addition to the wildcard allow that already covered them, and `llms.txt` at the site root gives AI agents/crawlers a clean markdown map of every review with a one-line summary and current rank/score. Every page also now sends `max-image-preview:large`, which is required (along with 1200px+ images, already in place) for Google Discover to show large thumbnails.

If you add a new review or rescore a tool, update `llms.txt`'s entry for it too, that file isn't auto-generated by `update_rankings.py` yet.

## Ranking system

Every tool now has a visible score (out of 10) and an overall rank (#1–16, cross-category, not per-category), shown as a badge on each homepage card, at the top of every review, and now in a sticky sidebar next to the ranked grid ("Full ranking") for quick jumping between reviews without scrolling the card grid. The current #1 gets a gold gem badge on its card, in the sidebar, and on its review page. Because there's now a real, visible rating on the page, each review's `Review` JSON-LD includes `reviewRating`, this is safe under Google's structured data guidelines specifically *because* the rating is shown on the page, not hidden. Methodology is explained on `about.html` under "How we rank." The "More reviews coming soon" placeholder grid always sits at the very bottom of the homepage, below the full-width close of the ranked/sidebar layout, those tools aren't part of the ranking until they get a real review.

**How to update it:**

1. Open `data/rankings.json`. Edit a tool's `score`, or add a new tool (needs `slug` matching its `reviews/{slug}.html` filename, `name`, `category`, `score`, and `previous_rank: null`).
2. Run `python3 scripts/update_rankings.py` from the site root.
3. The script recalculates every tool's rank from its score, compares it to the last run's rank, and injects an up/down/new/unchanged indicator (e.g. `▲2`, `▼1`, `NEW`, `-`) into the homepage card and the review page's rank line. It also reorders the homepage grid, rebuilds the sidebar list in the new order, moves the gem badge to the new #1, and updates the `ItemList`/`Review` JSON-LD to match. `data/rankings.json` is then overwritten with the new ranks saved as `previous_rank`, so the *next* run's deltas are correct.
4. Re-zip and redeploy.

On mobile (under 900px wide) the sidebar drops below the card grid instead of sitting beside it, there's no room for a fixed 260px column at that width.

The script is idempotent-ish but not fully safe to run twice in a row without new data, running it again immediately will show all `-` (no change), which is correct, but running it twice in the same sitting after only a partial edit could double-inject markup if you've hand-edited the HTML in between. Simplest to treat `data/rankings.json` as the only thing you hand-edit, and let the script own the HTML.

There's also a stray `scripts_rank_tmp.py` file in the site root, a leftover from building this feature that couldn't be deleted from this session's output folder. It's harmless (just a note pointing to the real script), safe to delete yourself.

## Differentiator sections

Every review now has a "What sets it apart" callout (the `.differentiator` box in `styles.css`) right after the intro paragraph, before the pricing breakdown. Each one has a real screenshot/animation (`images/{slug or tool}-example.webp`) captured directly from the vendor's own public marketing or product page, not from hands-on use by Solos Gems, plus a short excerpt explaining the one thing that tool does that's genuinely hard to replicate with a competitor. Each box is explicitly labeled "Example from [vendor.com], not independently tested by Solos Gems" so it's never mistaken for a first-hand testimonial. Most are short animated WebPs (3–18 frames) capturing real page scrolling/interaction; `midjourney-showcase-example.webp` is effectively a static image since only one frame was captured.

If you add a new review later, follow the same pattern: grab a real screenshot/animation from the vendor's site, write one honest sentence about what it does differently, and label the source the same way. Export as animated WebP, not GIF (see "Image format" below).

## Image format

All pricing screenshots and differentiator captures are animated WebP, not GIF. The originals were captured as GIF and converted with `ffmpeg -i in.gif -vcodec libwebp -loop 0 -q:v 60 -compression_level 6 -preset picture -an -vsync 0 out.webp`, which cut total image weight from about 21MB to about 4.2MB (roughly 80% smaller) with no visible quality loss, directly helping Core Web Vitals/LCP, which Google treats as a ranking signal. Browser support for WebP is effectively universal at this point, so there's no fallback needed. If you capture new screenshots, convert them the same way before adding them to `images/`. The old `.gif` originals are still sitting in `images/` unreferenced by any page (harmless dead weight, safe to delete yourself since they couldn't be removed from this session's output folder).

## Score radar + fun badges

Every review now shows a small radar chart under the spec plate, breaking the single overall score into the four methodology dimensions (value for price, capability, ease of use, trial safety) so readers can see *why* a tool scored what it did, not just the composite number. The four sub-scores per tool live in `data/rankings.json` alongside the existing `score` field (`value_score`, `capability_score`, `ease_score`, `trial_score`), and the chart itself is a hand-built inline SVG generated per page, no chart library or JS dependency.

Four tools also carry a small "fun badge" next to their name (on the homepage card and the review's rank line): Fireflies.ai is "Best Value," Descript is "Most Powerful," Calendly is "Easiest Start," and Beehiiv is "Safest Free Trial," each the standout tool in that specific sub-score. These are set via an optional `"badge"` field per tool in `data/rankings.json`.

Note: unlike the card grid, sidebar, and JSON-LD, `scripts/update_rankings.py` does not currently regenerate the radar charts or badges automatically, they were inserted as a one-time pass. If you change a tool's sub-scores or add a new tool, you'll need to hand-edit its radar SVG in `reviews/{slug}.html` (or write a small script following the same pattern used to build it) until this gets wired into the main ranking script.

## Tool finder quiz

The homepage now has a two-question quiz (`quiz.js`, styled via `.quiz-box` in `styles.css`) right below the hero: "what do you need help with" (auto-generated from the categories present in the data, so it never drifts out of sync) and "what matters most" (best value / most capability / easiest to use / safest to trial), which maps directly to the four sub-scores above. It recommends the top 1-3 matching tools with a link straight to the review. Everything is vanilla JS, no framework, no backend, and the tool data is embedded directly in `quiz.js` as a JSON array (mirrored from `data/rankings.json` via `data/quiz-tools.json`) so it works from a static file with no fetch/CORS concerns. If you rescore a tool or add a new one, regenerate `data/quiz-tools.json` from `data/rankings.json` and paste the updated array into the `TOOLS` constant at the top of `quiz.js`.
